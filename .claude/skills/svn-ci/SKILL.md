# SVN 提交信息生成技能

## 核心原则

1. **必须使用中文** 编写提交信息
2. **必须使用标准类型标签**：`[缺陷修复]`、`[代码优化]`、`[新增需求]`、`[文档更新]`/`[规则更新]`/`[脚本更新]`、`[版本提测]`、`[其它]`
3. **简洁明了**：一句话说明改动内容
4. **多改动按类型分类**：同一提交中不同类型的改动分别说明
5. **在当前目录执行**：用户确认提交信息后直接执行提交命令，无需切换目录

## 提交类型规范

### 1. [缺陷修复]
- **用途**：缺陷和 bug 修复
- **格式**：
  - 有 bug 号：`[缺陷修复] bug号：{编号}，{简要说明修复内容}`
  - 无 bug 号：`[缺陷修复] {简要说明修复内容}`
- **示例**：
  - `[缺陷修复] bug号：111111，修复quic模块大流量压力下core问题`
  - `[缺陷修复] 修复某模块内存泄漏问题`

### 2. [代码优化]
- **用途**：代码性能优化和结构优化
- **格式**：`[代码优化] {简要说明优化内容}`
- **示例**：
  - `[代码优化] libsubcommon修改，dpi_arrhash2代码优化`
  - `[代码优化] 删除无用函数和冗余代码`

### 3. [新增需求]
- **用途**：新增功能和需求
- **格式**：`[新增需求] {简要说明新增的功能}`
- **示例**：
  - `[新增需求] 添加quic协议xdr模块`
  - `[新增需求] 新增应用层协议名称打印函数`

### 4. [文档/规则/脚本更新]
- **用途**：文档、规则或脚本的更新
- **格式**：
  - 文档更新：`[文档更新] {说明}`
  - 规则更新：`[规则更新] {说明}`
  - 脚本更新：`[脚本更新] {说明}`
- **示例**：
  - `[文档更新] docker使用文档上传`
  - `[规则更新] idc30电信网安恶意文件规则更新`
  - `[脚本更新] 打包脚本更新`

### 5. [版本提测]
- **用途**：头文件和库文件的更新
- **格式**：
  - 指定版本：`[版本提测] {版本号}版本提测，{环境说明}头文件和库文件提交`
  - 最新代码：`[版本提测] 最新代码{环境说明}头文件和库文件提交`
- **示例**：
  - `[版本提测] 基础平台2030版本提测，欧拉x86环境头文件和库文件提交`
  - `[版本提测] 最新代码欧拉x86环境头文件和库文件提交`

### 6. [其它]
- **用途**：除上述5种外的其他提交操作
- **格式**：`[其它] {说明}`
- **示例**：
  - `[其它] magic文件类型识别小工具代码提交`
  - `[其它] 误修改，提交测试`

## 必须排除的文件

以下文件 **不要提交**：

### 自动生成文件
- `sub_out_*.c` / `sub_out_*.h`
- `*ConfFile.c` / `*ConfFile.h`

如果 SVN 之前有提交过这些文件，本轮重新生成后显示有修改，则需要提交。

### 版本号文件
- `main/svnver`
- `main/ver.h`

这些文件由构建系统自动更新，提交时无需手动提交。

### output 目录下的库文件
- `output/` 目录下的所有 `.so` 库文件（如 `output/binUbuntu_20_04/x86/haswell/lib/platform/*.so.*`）

这些库文件由各模块编译生成，不应随代码提交。
这些文件由构建系统自动更新，提交时无需手动提交。

## 生成步骤

1. **分析代码改动**
   - 运行 `git status` 或 `svn status` 查看修改的文件
   - 过滤掉自动生成文件（sub_out_*.*, *ConfFile.*）
   - 运行 `git diff` 或 `svn diff` 查看具体改动内容

2. **确定提交类型**
   - 根据改动内容选择最合适的提交类型
   - 如果是 bug 修复，确认是否有 bug 号
   - 如果是新增功能，描述新功能的作用
   - 如果有多种类型改动，按类型分别说明

3. **生成提交信息**
   - 使用规范的格式
   - 简洁明了地说明改动内容
   - 多个改动用分类列出

4. **输出格式**
   - 先输出提交标题（一行）
   - 如有需要，输出详细说明（多行，用数字或符号列出）
   - 最后给出提交命令

## 示例输出

### 单一改动示例
```
[新增需求] 新增应用层协议名称打印函数print_rt_public_name
```

### 复合改动示例
```
[新增需求] 新增应用层协议名称和天翼云出入向输出功能

1. 新增 print_rt_public_name 函数
   - 支持打印应用层协议名称
   - 通过 public_pid 查询协议表获取名称

2. 新增 print_rt_traffic_out_tyy 函数
   - 按电信天翼云全流量探针格式输出出入向

3. 更新回调表注册
   - 注册新增的两个输出函数
```

### 提交确认

生成提交信息后，**必须先向用户请求确认**，未获得用户明确确认前，不执行任何提交命令。
不同 Harness 使用不同的确认工具：

- **Claude Code / opencode**：使用 `AskUserQuestion` 工具向用户确认
- **Codex**：使用 `request_user_input` 工具向用户确认
- 其它不支持交互的 Harness：只输出待提交文件、提交信息和提交命令，不执行提交

调用确认工具时，先展示待提交文件和提交信息：

```
📋 即将提交的文件：
  - file1.c
  - file2.h

📝 提交信息：
  [类型] 提交说明
```

并提供以下选项供用户选择：

- **确认提交**：直接执行提交命令
- **修改提交信息**：用户说明需要修改的内容，重新生成
- **取消提交**：放弃本次提交

## 常用命令参考

| 命令 | 说明 |
|------|------|
| `svn status` | 查看工作目录状态（`?`=新增, `M`=修改, `D`=删除） |
| `svn diff` | 查看所有文件的详细改动 |
| `svn diff 文件路径` | 查看指定文件的改动 |
| `svn revert 文件路径` | 撤销本地修改（未提交前） |
| `svn commit -m "信息"` | 提交到仓库 |
| `svn update` | 更新工作目录 |
| `git svn rebase` | Git SVN 同步更新 |
| `git svn dcommit` | Git SVN 推送提交 |
